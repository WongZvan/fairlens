# FairLens 开发启动手册（开发前流程顺序）

> 配套 [01-技术开发文档.md](01-技术开发文档.md)（规格唯一事实源）使用；本手册只回答"按什么顺序把开发跑起来"。

## ① 远程仓库链接与推送（已完成 2026-10-24）

```
git remote add origin https://github.com/WongZvan/fairlens.git
git push -u origin main    # 稳定基线（设计文档 v0.1）
git push -u origin dev     # 日常集成分支
```

## ② GitHub 分支保护（UI 两分钟，时机 = M0 CI 就绪后）

保护依赖 CI 存在，M0 提交 workflows 后再配置：
- `main`：Require status checks（三门禁）+ **禁止 force push** + 不允许直接 push（仅合并）
- `dev`：**禁止 force push**
- Tags：保护 `v*` 前缀

## ③ 开发环境准备（M0 前，本机一次性）

- Node LTS（≥20）+ `corepack enable` 启用 pnpm
- Rust stable（rustup）+ MSVC Build Tools（Tauri Windows 依赖）
- 可选：VS Code + rust-analyzer / ESLint 插件

## ④ M0 启动流程（首个开发动作）

```
git switch dev
git switch -c feat/m0-scaffold        # 首个 feat 分支
# 按 01 文档 §3.5 顺序实施：
#   m0.1 Monorepo+CI 三门禁（lint/typecheck/test + actions 版本 pin + lockfile 入仓）
#   m0.2 packages/shared 全契约（含全部预留类型）+ zod 单测
#   m0.3 apps/desktop 壳+design-system 令牌+i18n 骨架+Rust 薄层骨架+角色门控路由骨架
#   m0.4 tools/keygen init（dev/prod 双密钥对）+ lease-api 契约 CI 冻结
# DoD：CI 全绿；空窗口以设计系统渲染；i18n 骨架就位
git switch dev && git merge --squash feat/m0-scaffold && git commit
git switch main && git merge dev       # M0 收口（可选 tag v0.1.0-m0）
```

## ⑤ 里程碑通用节奏（M1–M5 循环）

```
feat/<模块>（≤3 天，DoD=自身测试绿+CI 绿+不破坏既有）
  → squash 合回 dev
  → 里程碑全部模块完成 + §14 测试清单全绿
  → dev → main 合并收口 + tag v0.1.0-m<N>（预发布，不进 latest.json）
  → M5 收口后打 v0.1.0 正式版（进稳定通道）
```

## ⑥ 外部资源准备时机表（不要提前做）

| 资源 | 时机 | 参考 |
|---|---|---|

| Cloudflare 账号 + 双 KV namespace + 自定义域名 | **M2 开始前**（~1 天） | 01 §11.3 |

| 首批激活码 CSV（`keygen issue --env prod`） | 交付批次前 10 分钟 | 01 §11.6 Runbook |

## ⑦ 常用命令速查

```bash
# 分支
git switch -c feat/<模块> && git switch dev && git merge --squash feat/<模块>
# 回滚（三层）
git revert <commit>                          # 代码层（main 永不 force push）
# 发布回滚：发更高版本或 latest.json 指回旧版；提示词包：git revert dist/ 提交
# 灾备（M2 起）
wrangler kv key list --binding LEASE --env production   # KV 导出（CI 定期）
keygen issue --batch <修复批> --env prod ...            # 台账重放重建 KV
```
