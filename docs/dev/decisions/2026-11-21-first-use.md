# ADR：首用闭环（空白简历可写 / 姓名真实性 / 归档一致）

> 决策编号：总账 #128
> 日期：2026-11-21
> 状态：已实施
> 触发：codex 以「第一次使用能否写出自己的简历」重走浏览器流程，报 3 个首用阻断 + 2 个阶段性问题，并指出前一轮两项旧缺陷未修
> 相关：`docs/01` §4.1/§5.2/§5.7/§12.5/§14 · `packages/shared/src/resume.ts` · `apps/desktop/src/features/editor/` · `e2e/first-use.spec.ts`

## 1. 问题（全部在代码中复现）

| 级别 | 问题 | 根因 |
|---|---|---|
| P1 | 空白「基本信息」无法添加字段 | `SectionHeaderView` 对所有分区统一调 `insertEntry`；`BasicFieldView` 的「+」只挂在已有字段行尾 → 零字段时无入口。总账 #122 写的是「分区尾部 + 添加字段」，实现与决策不符 |
| P1 | 「你的姓名」是真数据 | `blank-doc.ts` 把占位文案写进 `profile.name`；导出无校验 → 归档/快照/PDF 都可能带假姓名 |
| P2 | 新增分区暴露内部类型键 | `SectionDialog` 默认 custom 并把「类型标识（英文，用于规则匹配）」摆在主表单 |
| 旧 | 归档可能读旧落盘版本 | 归档从 `persistence().getResume()` 取 `doc`；自动保存有 800ms 防抖，读到的可能是旧版本 |
| 旧 | 清空时保存失败仍报成功 | `replaceDoc` 忽略 `saveNow()` 的 `{ok}`，调用方无条件 toast 成功 |
| 阶段 | 库页底栏显示编辑器状态 | `StatusBar` 恒读 `editor-doc`，库页显示「约 N 字 · 自动保存」但没有任何卡片 |

## 2. 决策

### 2.1 空白基本信息：`basic` 分区用「添加字段」

- `insertSection({type:'basic'})` 只建 header；非 basic 分区保持 header + 空条目。
- `addBasicField` 扩参 `{ sectionId?, label }`：分区标题按钮用 sectionId 定位，插到分区末尾并把光标放进新字段；label 由 UI 传 i18n 文案（命令层不写死中文）。
- `SectionHeaderView` 按父分区 `attrs.type` 决定按钮语义：basic → 「添加字段」，其余 → 「添加条目」。
- 空分区（`childCount <= 1`）加 `.is-empty`，入口**常显**——首用时不应该靠悬停猜。

### 2.2 姓名：数据层可空，导出前拦截

- `Profile.name` 由 `z.string().min(1)` 改为 `z.string()`（T2 契约变更）。
- 空白简历 `profile.name = ''`；画布已有 `name || t('editor.namePlaceholder')` 占位显示，无需新增 UI。
- 新增纯函数 `lib/export-guard.ts`：`isNameMissing(name)`（trim 后为空）。PDF 与归档导出**统一先拦截**并 toast「请先填写姓名再导出」。
- 打印兜底：空名占位加 `.name-placeholder`，`print-shell.css` 在 `@media print` 隐藏，任何打印路径都不会把「你的姓名」印进纸面。
- 投影：`renderProjection` 对空名输出「姓名：（未填写）」，避免 AI 只看到空的「姓名：」。

**否决**：保留占位字符串 + 只做导出识别——归档与快照会长期存假数据，且「你的姓名」是合法输入时无法区分。

### 2.3 归档：正文取当前文档

- `resume.doc` 用 `st.doc`；`title` 用 `st.resumeTitle ?? row.title`；`row` 只提供 id/verticalId/status；`snapshots` 仍读库。
- 不再先 `flushPending`：归档要的是「用户此刻看到的内容」，不是「库里最后一次落盘的内容」；两者不一致时以前者为准。

**否决**：导出前强制 `saveNow()`——把「导出」变成隐式保存，改变手动模式的语义，且保存失败会阻断一个本可正常完成的导出。

### 2.4 清空失败可见

`replaceDoc` 返回 `Promise<{ok:boolean}>`（透传 `saveNow()`）；`clearToBlank` 仅在 `ok` 时 toast「已清空为空白简历」，失败走「清空失败，请重试」。

### 2.5 库页语义

`StatusBar` 的保存状态、字数统计、导出回执、`?` 入口仅在 `view === 'editor'` 渲染。真正的多简历库（新建另一份/切换/删除）仍属 m1.8——在 STATE 标为 **M1 收口阻塞项**，本轮不冒充已有能力。

### 2.6 分区对话框分层

标题（必填、autofocus）→ 类型下拉 → 「高级设置」折叠区（类型标识，默认 custom，不展开也能保存）。类型标识仍保留：它是未来按类型匹配规则（maxEntries 等）的显式入口，只是不该占主路径。

## 3. 验证

- 单测：`blank-doc`（空姓名）、`export-guard`（空/空白/有值）、`section-commands`（basic 只 header / 非 basic 有 entry / addBasicField 按 sectionId）、`doc-projection`（姓名未填写）、契约测试（空 name 允许）。
- E2E：`e2e/first-use.spec.ts` 两条——清空→添加字段→输入→导出被拦；库页状态栏无编辑器状态。
- 门禁：`test:coverage`（四包维持 ≥80）/ lint / typecheck / contract / build / e2e。
