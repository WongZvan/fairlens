# ADR：m1.8 简历库前置与多简历闭环

> 决策编号：总账 #129
> 日期：2026-11-21
> 状态：已定案（预览先行，交互实现待预览过目）
> 触发：codex 指出「m1.7→m1.8 的规格顺序与 STATE 的‘下一步 m1.8’冲突」；首用走查发现库页无多份简历闭环
> 相关：`docs/01` §3.5/§5.1/§5.7 · `docs/dev/modules/m1/m1.7-import.md` · `m1.8-library-home.md` · `docs/design-previews/fairlens-library-m18-preview.html`

## 1. 决策

### 1.1 顺序：m1.8 前置、m1.7 后置（T3）

M1 尾部由 `m1.6 → m1.7 导入 → m1.8 库` 改为 `m1.6 → m1.8 库 → m1.7 导入`。

理由：
1. **首用闭环**：用户第一次使用的完整链路是「激活 → 库 → 新建/打开 → 写 → 回库」；缺库页就没有入口，示例与清空只是补丁。
2. **导入的落点**：导入产物是一条新简历记录，需要库页的「新建/打开」与卡片管理先成立；先做导入会缺落点。
3. **m1.7 本就暂缓**（2026-11-04 用户指示），顺序后置不改变它的状态。

按 §10.5 T3 传播：§3.5 序列表、§5.1 规格、两模块 MD、导航表、STATE、验收清单全部更新；本 ADR 与总账入册。

**工期/成本影响：无。** 模块集合与工作量不变，只是顺序调整；§11.2 是年度现金成本表，无逐模块工期条目，无需改数值；§1.6 R2 的 55–70 理想日区间亦不变。

### 1.2 导入区在 m1.8 的呈现：禁用占位 + 人话

m1.7 未接通时，库页导入区**保留布局但整体不可操作**，用户可见文案固定为「导入暂未开放」（不出现模块号；归属 m1.7 只记在本 ADR 与任务表），不出现可点但完不成的按钮。

**否决**：完全隐藏（首屏布局在 m1.7 还要再变一次，且用户不知道导入存在）；先接「粘贴文本」（实质是把 m1.7 一部分提前，范围失控）。

### 1.3 归档 = 软归档

卡片「归档」= `status='archived'`：卡片置灰、默认不参与统计，「显示归档」开关可切回；可取消归档。

**否决**：归档=导出 .fairlens（与 §5.1「置灰不参与统计」不符，且 .fairlens 导出已属「备份与恢复」，m5.1）。

### 1.4 首启示例保留为卡片

空库首启仍自动建一份「示例简历」记录；模板快捷卡**新建空白简历**（各自 templateId），绝不打开同一份示例。删光记录后进入空态（模板卡 + 禁用导入区）。

**旧库升级**：`sampleSeeded` 标记缺失但库内已有简历 → **只补标记、不播种**；只有“标记缺失且库为空”才播种。避免老用户升级后多出一份示例。

**否决**：首启直接空库（首次打开没有可看的样板；现有用户库里的示例还要另外处理）。

### 1.5 切换保护：不新增关闭意图

切换简历的路径固定为「编辑器 → 返回简历库（走 §5.7 保护）→ 打开另一份」。库页不叠在编辑器上，所以 `CloseGuard` 仍只有 `window-close` / `back-library`；不新增 `switch-resume`，避免为不存在的 UI 加状态机。

### 1.6 未开放能力一律不装样子

- 导入区：禁用 + 人话（m1.7）。
- 备份与恢复：禁用 + 「未开放」（m5.1）。
- 评估分徽章 / 批注数：不渲染（M4）。
- 「配置 AI」引导卡：不出现（m3.2）。
- 垂类筛选 / 搜索：不做（未排期）。

## 2. 技术要点

- **持久层端口扩展**：`listResumeMetas()` 由「只查 active、无 templateId」改为返回**全部状态** + `templateId` + `snapshotCount`（SQL 用 `template_id` 列与快照数子查询；memory 同步）。这是库页归档筛选与卡片元信息的前提。
- **状态层**：新增 `stores/library.ts`；`editor-doc.openCurrent()` 重构为 `openResume(id)`，示例播种从编辑器移到库页。
- **模板常量**：`CommandBar` 内的三套模板选项抽到 `features/templates/choices.ts`，库页模板卡与命令栏下拉同源。
- **删除**：复用 `ConfirmDialog`，正文含快照数并提示「可先归档保留」。
- **删除口径（四表级联，SQLite 原子）**：删除一份简历必须同时清掉 `resume_snapshots` / `review_sessions` / `ai_patch_log`。`resume_snapshots`、`review_sessions` 在 v1 已有 `ON DELETE CASCADE`；`ai_patch_log` 没有外键 → **v2 迁移重建该表补 `FOREIGN KEY(resume_id) REFERENCES resumes(id) ON DELETE CASCADE`**（SQLite 不能 `ALTER TABLE ADD CONSTRAINT`；先清孤儿再拷贝）。sqlx 0.8.6 默认 `foreign_keys=ON`（已核源码），`deleteResume` 只发**单条** `DELETE FROM resumes`，级联在一个语句内原子完成；适配器加载断言 `PRAGMA foreign_keys = 1`，不成立就报错，不静默留孤儿。Memory 侧显式清 `snapshots`（review/patch 暂无内存实现）。

## 3. 验收（可判定，替换“单测/E2E 绿”）

1. 首启示例卡存在；模板卡新建第二份（标题「我的简历」、对应 templateId），示例仍在；打开后画布为空、`data-template` 正确。
2. 返回库 → 打开另一份：标题/模板/内容不串。
3. 手动模式改字 → 返回库弹三键框；取消留在编辑器；不保存回库且另一份未受影响。
4. 重命名后卡片标题更新，重开仍在（真窗 SQLite）。
5. 归档后默认隐藏、开关后可见且置灰；取消归档恢复。
6. 删除确认列快照数并建议归档；确认后卡片与快照一并消失；删光进空态。
7. 导入区禁用不可点；备份与恢复「未开放」；卡片无评估徽章。

E2E 覆盖 1–3、5、6（浏览器内存持久层）；4、6 的 SQLite 部分与真窗行为进 `acceptance/M1.md §14`。
