# ADR：契约放宽（分区类型 / 页头字段 / 日期 / 要点缩进）

> 决策编号：总账 #121 / #122 / #123（缺陷修复见 #120）
> 日期：2026-11-13
> 状态：已定案（用户逐项四选一拍板）
> 关联：§4.1 ResumeDoc / §4.2 TemplateManifest / §5.2 权限矩阵 / §5.3 节点映射 / m1.3 / m1.4 / m1.5
> 背景：用户真机试用后报 6 条（其中两条被诊断为 3 个真 bug，见 #120；余下是契约限制）

## 1. 为什么放宽

原契约的封闭枚举与固定字段在 v0.1 打样期是**刻意约束**（#5 版式锁定 + schema 封闭），目的是让版式不可破坏。真机试用暴露的是另一类问题：**内容装不进去**。

- 分区只允许五类 → 用户写不了「自我评价」「证书」「工作经历（与实习区分）」；
- 页头只有三个字段 → 电话/邮箱/城市/个人网站挤在一行 `contactLine` 里；
- 日期只认 `YYYY.MM` → 写「2022」「大三」「2022年9月」全部被拒；
- 要点只有平铺一层 → 无法表达「子要点」。

**关键判断**：放宽的是「内容槽位的种类与文本自由度」，不是「版式自由度」。字体/字号/颜色/页边距的任意数值仍然禁止（§5.2 不变），所以「版式不可破坏」这条护城河没有被挖开。

## 2. 四个决定与理由

### 2.1 `Section.type` 放开为自由字符串（#121）

- `SECTION_TYPES` → `BUILTIN_SECTION_TYPES`（仍是五值，供 manifest 规则与新建对话框的预设标题用）
- `Section.type: z.string().min(1)`
- **为什么不是「加一个 custom 类型」**：用户明确要「完全自由」。加 custom 只是把封闭集扩到 6 个，下次要「证书」又得改契约。
- **代价与处理**：
  - manifest 的 `SectionRule` 只对命中的 type 生效 → 自定义分区**不限条数**（`entry-duplicate.ts` 现有 `rule &&` 判空已天然支持，无需改）
  - duo 分栏：未知 type 归主栏（`isSideSection` 只认 basic/skill）
  - 大纲空标题回落：有 i18n 映射用映射，否则用 `type` 原文
  - 新建对话框：标题必填 + 类型（内置五类下拉 / 自由输入，默认 `custom`）

### 2.2 `Profile.fields?: BasicField[]`（#122 之一）

- 三项固定字段（name/headline/contactLine）**保留**：`printCSS`、三套模板、`doc-projection` 都依赖它们，替换会把改动面扩到 §8 模板体系
- 新增 `fields[]` 存「其他字段」（籍贯/政治面貌/个人网站…），复用 `BasicField` 契约（label/value/href）
- 页头编辑对话框：三项固定 + 动态列表（增删改）
- **两者都保留、各管一摊**（用户选择）：页头管「人」，基本信息分区管「求职相关事实」

### 2.3 `Entry.start/end` 放开为自由文本（#122 之二）

- `YearMonth` 保留（旧值仍合法），但字段类型改 `z.string()`
- 校验降级：**仅当两端都匹配 `YYYY.MM` 时**校验 `end ≥ start`；其余一律放行
- `ongoing` 语义不变（「至今」），`ongoing && end` 仍然拒绝（逻辑矛盾）
- UI：删除 `dateInvalid` 错误分支（自由文本不可能"格式错"），placeholder 改为示例
- **已知代价**：失去可靠排序依据。当前没有按时间排序的功能；M4 评估若需要，先做归一化而不是回头收紧契约

### 2.4 `Bullet.depth?: 0|1|2`（#123）

- 深度枚举（不是任意数字）：简历两层足够，三页以上三层缩进会让行宽过窄
- `0` 不落库（保持旧文档字节等价）
- `Tab` 加深 / `Shift+Tab` 减淡，`depth=0` 时 `Shift+Tab` 不动
- **导出保留**：`data-depth` 驱动 CSS `margin-left`，编辑/预览/printCSS 同源；`alignBlockDiff` 的 bullet payload 纳入 depth（否则改缩进不算变更，快照会漏）
- Word 生成器（m5.1 未实现）在契约层标注「必须读 depth」

## 3. 对既有决策的影响

| 既有决策 | 影响 |
|---|---|
| #5 版式锁定+schema 封闭 | **未破坏**：版式仍由模板锁定，放开的是内容槽位 |
| #78 历史条目永不改写 | 本条未改写任何历史条目，只新增 120–123 |
| #117 profile 契约 | 扩展（加 fields），不替换 |
| #118 大纲空标题回落类型名 | 逻辑保留，映射缺失时回落 type 原文 |
| 附录 B DDL | **无需迁移**：doc_json 是 JSON 文本，新字段天然兼容旧行；旧行缺字段时 zod 可选字段通过 |

## 4. 旧数据兼容

- 旧 `doc_json`：`Section.type` 仍是五值之一（合法）、`Entry.start/end` 仍是 `YYYY.MM`（合法）、无 `profile.fields` / `bullet.depth`（可选缺省）→ **全部通过新 schema**
- `repair-doc.ts` 的数字日期归一保留（旧库 `start: 2022.09` 浮点）
- 无需 SQLite 迁移（`user_version` 不变）

## 5. 明确不做

| 不做 | 理由 |
|---|---|
| 页头替换掉 name/headline/contactLine | 模板与 printCSS 依赖，要连带改 §8；另立项 |
| 自定义分区也纳入 maxEntries | 用户选择「不限条数」；需要时再按分区加 `maxEntriesOverride` |
| 日期智能解析（`2022年9月` → `2022.09`） | 自由文本的目的就是不再规训用户；解析错了反而更糟 |
| 缩进超过 2 层 | 行宽会塌 |
| 分区排序 UI | 现有顺序=文档顺序，新增分区追加到末尾；拖拽排序随 m1.8 库首页一起做 |

## 6. 验证

- 单测：`section` 自由 type 往返与 outline 回落、上限判定（未知 type 不拦）、`Profile.fields` 往返、日期自由文本解析矩阵（`2022`/`2022年9月`/`2022.09.15`/`大三`/`2022.13`）、`depth` 往返与 Tab 夹取
- 契约测试：`packages/shared/src/contracts.test.ts` 补新字段
- 真窗：新增「自我评价」分区 → 加两条 → 重开仍在；页头加「籍贯」→ 重开仍在；日期填「大三」→ 保存成功；Tab 缩进两层 → 导出预览缩进一致
