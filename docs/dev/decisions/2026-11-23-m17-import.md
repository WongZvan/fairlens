# ADR：m1.7 导入管线（解析 + 条件检查）

> 状态：**修订定案（2026-11-23，第二轮）**，实现待预览放行。决策总账 #130。
> 关联：docs/01 §1.3 用户故事 3 · §4.1 ResumeDoc · §5.1 库页导入区 · §5.6 导入 · §5.7 关闭保护；m1.4 大段粘贴入口；m3.5 LLM 接入点。
> 用户拍板（2026-11-23）：① 结构化=**本地启发式**（m1.7 不接 LLM）；② 依赖=**mammoth + pdfjs-dist**；③ 向导=**主窗内独立全屏视图**（不新建 OS 窗口，真第二窗口仍归 m2.3）。
> 复核修订（2026-11-23，codex 三轮）：**保留逐区核对能力，但取消“每份文件必须完整核对”**；补齐超限条目的跨层保留与未归类内容的最终去向。

## 1. 背景与约束

- m1.8 已收口：库页有「新建/打开/归档/删除」闭环，导入区目前是**禁用占位**（实现后替换为真入口；当前进度以 STATE 为准）。
- 规格原描述为「DOCX/PDF/粘贴 → LLM 结构化 → 逐区确认」。**LLM/Key 属 m3.5**，m1.7 不能依赖用户 Key。
- 约束：解析**纯本地**，文件不上传；导入产物=**一条新简历记录**（不覆盖当前文档）；版式锁定，导入不携带字体/字号/颜色。

## 2. 决策

### 2.1 条件检查：检查工作随解析结果变化

导入后**不强制**走完整逐区核对；按解析结果分三种路径：

| 解析结果 | 默认路径 |
|---|---|
| 分区/条目识别清楚（无待处理项） | 摘要「识别到 N 个分区，无待处理内容」→ **导入并打开**；旁边可选「先检查内容」 |
| 有疑点（未归类/低置信/超限）但文字已提取 | 摘要「有 N 处需要检查」→ 只展开问题分区/原文片段；「导入并打开」始终可见，按钮上方**逐项列明去向** |
| 无文字层/无法可靠提取 | 明确原因 + 换 DOCX/粘贴路径；**不创建空简历** |

- 「先检查内容 / 检查 N 处」进入完整核对视图；正常分区默认收起，问题项置顶。
- 三条底线：① 每段提取文字都有明确去向；② 提示说具体问题（哪个分区/哪一条），不报笼统置信度；③ 导出前再守一次关（见 2.5）。
- 模板选择不在向导内：默认经典单栏，进入编辑器后可切换（当前三套模板共用同一 maxEntries 规则；未来模板差异时导出前按当前模板复核）。

### 2.2 解析来源与依赖

| 来源 | 实现 | 边界 |
|---|---|---|
| 粘贴文本 | 纯文本按空行/行首符号切块 | 保留要点层级；不解析 HTML |
| DOCX | `mammoth.convertToHtml` → **白名单清洗** → 块化 | 表格逐单元格平铺为文本行；图片忽略并提示数量 |
| PDF | `pdfjs-dist` `getTextContent()` → 按 y/x 聚行、段落合并 | 扫描件/无文本层 → 明确报错；分栏顺序低置信 → 标记待检查并提供原文对照 |

- 文件读取：Rust 命令 `read_import_file(path, max_bytes) -> Vec<u8>`（上限 **20MB**），不装 `plugin-fs`；capability 增 `dialog:allow-open`。
- 拖入：窗口 `dragDropEnabled: true` + `onDragDropEvent`；dnd-kit 为 PointerSensor（大纲拖拽），实现时回归。
- 浏览器模式：`<input type=file>` + `File.arrayBuffer()` 走同一解析管线；不显示假拖入。

### 2.3 流程与 UI

- **主窗内容区全屏视图**（保留标题栏三键），不是 OS 第二窗口（真窗口基建归 m2.3），不是浮层。
- 结构：**来源 → 结果/检查**；**取消独立“完成”页**——核对视图底部的「导入并打开」即创建动作。
- 来源步**唯一主路径**：先选文件或输入非空文本，才能继续；空内容就地说明原因，底栏不提供绕过按钮。
- 核对视图：左侧分区导航**真实滚动定位**（含「待整理内容」「暂不显示」），右侧分区卡可改标题/类型、条目字段与要点；「查看提取原文」抽屉可逐块对照并指派。
- 内部类型标识（basic/experience 等）不出现在用户界面；分区类型用中文名。
- 取消/返回：确认「放弃本次导入？」；确认后回库页，未创建任何记录。
- 完成：创建成功后直接打开编辑器；不保留独立完成页。

### 2.4 未归类内容的去向（不静默丢弃）

- 解析后无法归类的块默认保留为 **「待整理内容」分区**（`type='inbox'`，自定义分区；每块转为一个条目/要点），导入后在画布与大纲中可见、可改名、可移动到其他分区。
- 核对视图中每块可：指派到已有分区 / 保留在「待整理内容」/ **显式丢弃**（默认不是丢弃）。
- 「导入并打开」上方固定摘要：`3 块将放入「待整理内容」· 1 条经历暂不显示`；摘要即用户对内容的最终去向确认。
- 导出前若「待整理内容」仍非空，纳入导出前检查（2.5）。

### 2.5 超限条目的跨层保留（契约新增 `Entry.hidden`）

**问题**：现有画布转换会放入全部条目，PDF 打印画布；若导入时把超限条目排除在画布外，再次保存会被序列化丢失。仅靠“排序”无法表达“保存在数据里但不显示”。

**方案**（类型先行，向后兼容）：

- `Entry` 增可选 `hidden?: true`（缺省=显示；zod 契约与 docs/01 §4.1 同步）。
- 画布：**所有条目都渲染**；`hidden` 条目带「暂不显示 · 超出模板上限」徽标，仍可编辑；条目菜单可切换显示/暂不显示。
- 打印/PDF：`@media print` 隐藏 `[data-hidden="true"]` 的条目——简历成品与 PDF 不含隐藏条目。
- 回写：`pmToResumeDoc` 读取 `hidden` 属性并写回文档，**再次保存不丢失**；快照 diff 纳入 `hidden`；归档（.fairlens）保留全部条目（备份语义，不是成品导出）。
- Word/批注版/长图（M5）必须同样读取 `hidden`；在规格 §9 标注。
- 导入时：超出当前分区 `maxEntries` 的条目默认标为 `hidden`；核对界面**每条**都显示「显示 / 暂不显示」并可切换；导入摘要列出暂不显示的条目名称。
- **导出前检查**：若存在 `hidden` 条目或非空「待整理内容」，PDF/归档导出前弹检查框，逐条列出影响（「这 2 条不会出现在 PDF」），用户可「去处理」或「仍然导出」。
- 现有 `maxEntries` 仅用于结构复制 gating；本模块新增渲染/导出语义，测试覆盖往返与打印。

### 2.6 落库、失败与关闭保护

- 解析阶段**不建记录**；仅在「导入并打开」时一次性创建（复用 library 写入串行链与 `WriteOutcome`）。
- 创建成功 → `openResume(id)`；列表刷新失败 → 提示「已创建但列表未刷新」，不重复创建。
- 解析失败/无文本：留在结果页并显示可操作错误，不产生记录。
- 向导进行中 = **未完成状态**（§5.7）：关窗走 CloseGuard「丢弃并关闭 / 继续编辑」；离开需确认丢弃草稿。

### 2.7 接口留槽（m3.5）

- `ImportStructurer`：`structure(blocks, ctx): Promise<ImportDraft>`。
  - m1.7 唯一实现 `heuristicStructurer`（纯函数、无 IO、可单测）。
  - m3.5 新增 LLM 实现，复用本模块的**条件检查/未归类/超限/导出前守关**，不重写 UI。

### 2.8 入口

- 库页导入区替换为真入口：拖入 + 浏览 + 粘贴文本；空态恢复「投放区放大居中 + 三模板快捷」。
- m1.4 大段粘贴气泡「去导入」打开向导并**预填该次文本**；导入完成打开新简历，原文档不受影响。

## 3. 否决方案

| 方案 | 否决理由 |
|---|---|
| 每份文件强制完整逐区核对 | 用户主路径过重；codex 三轮复核均指出应只检查疑点 |
| 解析完直接打开、完全无核对 | 双栏 PDF/表格/装饰性简历易错分区，漏字到导出才发现 |
| m1.7 接 LLM 结构化 | 需提前 m3.5 的 Key/连接管理；离线不可用 |
| 零依赖自研 DOCX/PDF 解析 | 编号/表格/分栏/编码边界多，维护成本高 |
| 真 Tauri 第二窗口 | 需提前 m2.3 窗口基建与跨窗状态同步 |
| 仅排序表达超限 | 无法证明再次保存不丢隐藏条目；`hidden` 显式契约可测 |
| 未归类静默丢弃或阻断导入 | 前者丢内容，后者把整理成本前置；`待整理内容` 分区兼顾 |

## 4. 验收锚点

`acceptance/M1.md §15`：三来源、条件检查（干净/疑点/无文本）、未归类去向、`hidden` 往返与打印、导出前守关、落库/失败/未完成态、拖入与浏览器回退、去导入入口。
