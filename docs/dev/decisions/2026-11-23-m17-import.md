# ADR：m1.7 导入管线（解析 + 条件检查）

> 状态：**修订定案（2026-11-23，第三轮用户拍板）**，实现待预览放行。决策总账 #130。
> 关联：docs/01 §1.3 用户故事 3 · §4.1 ResumeDoc · §5.1 库页导入区 · §5.6 导入 · §9 导出；m1.4 大段粘贴；m3.5 LLM 接入；m5.1 导出。
> 用户拍板（2026-11-23）：① 结构化=**本地启发式**（m1.7 不接 LLM）；② 依赖=**mammoth + pdfjs-dist**；③ 向导=**主窗内独立全屏视图**（真第二窗口归 m2.3）。
> 第三轮修订（同一日，codex 两轮复核）：**maxEntries 改为篇幅建议（软上限）**、**「待整理内容」算成品直到处理完**、**大段粘贴改“粘贴前先选”**；**撤销 `Entry.hidden` 方案**。

## 1. 背景与约束

- m1.8 已收口：库页有「新建/打开/归档/删除」闭环，导入区目前是**禁用占位**（实现后替换；当前进度以 STATE 为准）。
- 规格原描述为「DOCX/PDF/粘贴 → LLM 结构化 → 逐区确认」。**LLM/Key 属 m3.5**，m1.7 不能依赖用户 Key。
- 约束：解析**纯本地**，文件不上传；导入产物=**一条新简历记录**（不覆盖当前文档）；版式锁定，导入不携带字体/字号/颜色。
- **画布所见即导出**是产品承诺：纸面不得出现“编辑时可见、导出时消失”的内容。

## 2. 决策

### 2.1 条件检查：两段式，措辞不承诺“机器已证明完整”

**第一段：源文件 → 提取文本**
- PDF 逐页记录提取结果：每页是否有文本、字符数、低置信（分栏/表格顺序）；**某页无文本** = 待确认项（不能因整份文件“有文字”就放行）。
- DOCX 记录图片数量并提示「图片中的文字不会导入」；表格逐格平铺。
- 摘要用诚实措辞：**「文件文字已提取：4/4 页 · 未发现需确认项，建议打开后快速检查」**，不写「无待处理内容」这种完整承诺。

**第二段：提取文本 → 简历分区**
- 识别清楚（无未归类/低置信/缺页）→ 摘要 + **导入并打开**；可选「先检查内容」。
- 有疑点 → 只展开问题项（未归类/低置信/缺页），给具体位置（页/分区/条目）。
- 无文字层 → 明确报错 + 换 DOCX/粘贴；不创建空简历。
- 三条底线：每段提取文字都有明确去向；提示说具体问题；导出前守关（2.4/2.6）。

### 2.2 解析来源与依赖

| 来源 | 实现 | 边界 |
|---|---|---|
| 粘贴文本 | 纯文本按空行/行首符号切块 | 保留要点层级；不解析 HTML |
| DOCX | `mammoth.convertToHtml` → **白名单清洗** → 块化 | 表格逐单元格平铺；图片忽略并提示数量 |
| PDF | `pdfjs-dist` `getTextContent()` → 按 y/x 聚行、段落合并 | **逐页**记录有无文本；扫描页/无文本页标记待确认；分栏低置信给原文对照 |

- 文件读取：Rust `read_import_file(path, max_bytes) -> Vec<u8>`（上限 **20MB**），不装 `plugin-fs`；capability 增 `dialog:allow-open`。
- 拖入：窗口 `dragDropEnabled: true` + `onDragDropEvent`；dnd-kit 为 PointerSensor（大纲拖拽），实现时回归。
- 浏览器模式：`<input type=file>` + `File.arrayBuffer()` 走同一解析管线；不显示假拖入。

### 2.3 流程、核对与原文对照

- **主窗内容区全屏视图**（保留标题栏三键）；不是 OS 第二窗口（归 m2.3），不是浮层。
- 结构：**来源 → 结果/检查**；取消独立「完成」页，核对视图底部「导入并打开」即创建动作。
- 来源步唯一主路径：先选文件或输入非空文本才能继续；空内容就地说明，无底栏绕过。
- 核对视图：
  - 左侧导航**真实滚动定位**到分区/「待整理内容」/问题项；
  - 分区标题与字段、条目 org/role/日期、要点文本**可编辑**，改动写回草稿（不因后续操作复位）；
  - 「查看提取原文」展示**不可变提取块**（页码/来源位置 + 每块当前去向），不是把结构化字段重新拼回；未指派的块必须在「待整理内容」或用户显式丢弃；
  - 界面不出现 `basic`/`experience` 等内部类型标识。
- 取消/返回：确认「放弃本次导入？」；确认后回库页，不创建任何记录。
- 成功：创建后直接打开编辑器；不保留完成页。

### 2.4 「待整理内容」：算成品，直到用户处理完

- 未归类块默认进入 **「待整理内容」分区**（`type='inbox'`），每块可指派到正式分区、保留、或**显式丢弃**。
- **该分区是真实简历分区**：画布与 PDF/Word 都会包含它；不制造“纸面可见、导出消失”。
- 导入摘要固定写：`3 块将放入「待整理内容」，会随简历一起导出`。
- **可交付语义**：待整理内容非空、或篇幅明显超出建议上限时，导出前提示「这份简历还不可交付：PDF 会包含 3 块待整理内容」；用户可「去处理」或「仍然导出」。提示与导出结果一致——导出**包含**它，不是遗漏它。
- `.fairlens` 归档是备份：保留全部数据，**不**弹“内容会遗漏”的成品警告。

### 2.5 篇幅：`maxEntries` 作为建议（软上限）

- **导入全部条目**，不截断、不隐藏；`maxEntries` 保留为 manifest 的篇幅建议与结构复制 gating。
- 超出建议上限时，核对界面与分区卡提示：**「该分区 9 条，建议上限 8 条；导出会正常分页，简历可能偏长」**，不阻止导入、不改变数据。
- **撤销 `Entry.hidden`**：不新增显示状态字段；字数统计、AI 读取投影、搜索、大纲、快照对比、m3.5 LLM 导入都按「全部条目都是简历内容」处理，口径一致。
- 导出 PDF/Word：全部条目正常参与分页（现有分页能力已支持）。
- 修订此前 #79「溢出勾选保留」的硬限制口径；本条为最新口径。

### 2.6 落库、失败与关闭保护

- 解析阶段**不建记录**；仅「导入并打开」时一次性创建（复用 library 写入串行链与 `WriteOutcome`）。
- 创建成功 → `openResume(id)`；列表刷新失败 → 提示「已创建但列表未刷新」，不重复创建。
- 解析失败/无文字：留在结果页并显示可操作错误，不产生记录。
- 向导进行中 = **未完成状态**（§5.7）：关窗走 CloseGuard「丢弃并关闭 / 继续编辑」；离开需确认丢弃草稿。

### 2.7 接口留槽（m3.5）

- `ImportStructurer`：`structure(blocks, ctx): Promise<ImportDraft>`。
  - m1.7 唯一实现 `heuristicStructurer`（纯函数、无 IO、可单测）。
  - m3.5 新增 LLM 实现，复用两段式检查/待整理内容/软上限/导出守关，不重写 UI。

### 2.8 大段粘贴入口：粘贴前先选

- 现有行为是**先插入、后出气泡**；m1.4 的提示文案只建议走导入，没有“去导入”按钮。
- m1.7 改为**粘贴前选择**：检测到大段粘贴（>300 字符或多段落）时，先弹轻量选择：
  - **贴到当前简历**（走原粘贴管线）；
  - **导入为新简历**（打开导入视图并预填该次文本，当前文档不变）；
  - 取消（不插入）。
- 不采用“插入后撤回”：无法可靠区分本次插入与用户此前编辑，撤销失败会给错误承诺。
- 库页导入区仍保留独立入口（拖入 + 浏览 + 粘贴）。

## 3. 否决方案

| 方案 | 否决理由 |
|---|---|
| `Entry.hidden`（纸面可见、导出消失） | 违反“画布所见即导出”；影响字数/AI/搜索/大纲/快照/导出全链路，且用户需脑算成品 |
| 硬上限 + 纸外内容托盘 | 产品上成立，但需新增托盘数据/UI/各导出协同，M1 成本过高；留作未来触发器 |
| 未归类静默丢弃 / 阻断导入 | 丢内容或把整理成本前置；「待整理内容」分区 + 明确去向更稳 |
| 每份文件强制完整逐区核对 | 主路径过重；条件检查只在有疑点时展开 |
| 粘贴后“去导入” | 原文档已被修改；“撤回本次粘贴”不可靠 |
| m1.7 接 LLM 结构化 | 需提前 m3.5 的 Key/连接管理；离线不可用 |

## 4. 验收锚点

`acceptance/M1.md §15`：两段式检查（含无文本页）、真实原文块与去向、可编辑草稿、软上限全量导入/分页、待整理内容随成品导出与守关、落库/失败/未完成态、粘贴前选择、浏览器回退。
