# ADR：m1.7 导入管线（解析 + 逐区确认）

> 状态：**已定案（2026-11-23）**，实现待预览放行。决策总账 #130。
> 关联：docs/01 §5.1 库页导入区 · §5.6 导入 · §4.1 ResumeDoc · §3.5 模块顺序；m1.4 大段粘贴入口；m3.5 LLM 接入点。
> 用户拍板（2026-11-23）：① 结构化=**启发式 + 逐区确认**（m1.7 不接 LLM）；② 依赖=**mammoth + pdfjs-dist**；③ 向导=**主窗内独立全屏视图**（不新建 OS 窗口，真第二窗口仍归 m2.3）。

## 1. 背景与约束

- m1.8 已收口：库页有「新建/打开/归档/删除」闭环，导入区是**禁用占位**（m1.7 接通后替换为真入口）。
- 规格 §5.6 原描述为「DOCX/PDF/粘贴 →（用户 Key）LLM 按 ResumeDoc 结构化 → zod 修复 → 逐区确认」。**LLM/Key 设置属 m3.5**，m1.7 不能依赖用户 Key。
- 约束：解析**纯本地**，文件不上传（§13 最小数据原则）；导入产物=**一条新简历记录**（不是覆盖当前文档）；模板版式锁定，导入不携带字体/字号/颜色。

## 2. 决策

### 2.1 无 LLM 的结构化：启发式，接口留槽

- `ImportBlock[]`（线性块：heading/para/bullet/table-row）→ **启发式结构化器** → `ResumeDoc` 草稿 + 警告。
- 定义 `ImportStructurer` 接口（类型先行，P3）：`structure(blocks, ctx): Promise<ImportDraft>`。
  - m1.7 唯一实现：`heuristicStructurer`（纯函数，无 IO，可单测）。
  - m3.5 新增 LLM 实现，**不重写向导与确认 UI**。
- 启发式范围：
  - 分区标题→类型映射（内置五类关键词 + 自定义分区名保留）；
  - 日期区间/「至今」识别 → Entry.start/end/ongoing；
  - 要点符号（•/-/·/◆/数字）与缩进 → Bullet.depth 0–2；
  - 顶部姓名/求职意向/联系方式 → Profile + basicFields；
  - 技能行（分隔符切分）→ SkillGroup；
  - **无法归类的块进入「未归类」池**，确认界面可指派到分区，不静默丢弃。

### 2.2 解析来源与依赖

| 来源 | 实现 | 边界 |
|---|---|---|
| 粘贴文本 | 纯文本按空行/行首符号切块 | 保留要点层级；不解析 HTML |
| DOCX | `mammoth.convertToHtml` → **白名单清洗**（复用既有 schema 清洗思路）→ 块化 | 表格逐单元格平铺为文本行（§5.6）；图片忽略并提示数量 |
| PDF | `pdfjs-dist` `getTextContent()` → 按 y/x 聚行、段落合并 | 扫描件/无文本层 → 明确报错并建议 DOCX/粘贴；分栏顺序为启发式，低置信时警告 |

- 文件读取：新增 Rust 命令 `read_import_file(path, max_bytes) -> Vec<u8>`（默认上限 **20MB**），不安装 `plugin-fs`；capability 增 `dialog:allow-open`。
- 拖入：窗口 `dragDropEnabled: true` + Tauri `onDragDropEvent` 取路径。**dnd-kit 用 PointerSensor（大纲拖拽），不受 OS 文件拖放开关影响**；实现时回归大纲拖拽。
- 浏览器模式（`pnpm dev`）：无 Tauri 拖放/文件命令 → 用 `<input type=file>` + `File.arrayBuffer()` 走同一解析管线。

### 2.3 向导形态与流程

- **主窗内容区全屏视图**（无库页/编辑器 chrome，保留系统标题栏与三键），不是 OS 第二窗口（真窗口基建归 m2.3），不是浮层。
- 三步：**来源 → 解析与逐区确认 → 完成**；解析中显示分阶段进度（读取/抽取/结构化）。
- 确认界面：
  - 左侧分区导航（数量、警告、未归类池）；右侧分区卡；
  - 分区标题/类型可改；条目 org/role/日期可改；要点文本可改、可删；
  - **未归类块**可指派到分区或丢弃（丢弃需显式操作）；
  - 顶部可切**目标模板**（默认经典单栏）；模板影响 maxEntries 与溢出提示；
  - 警告区：缺姓名、PDF 低置信、未归类数量、超出模板上限。
- 完成步：简历标题（默认取姓名/「导入的简历」）+ 模板摘要 + 「创建并打开」。

### 2.4 溢出策略（不改 schema）

- 规格 §5.6：**不截断**；超出模板 `maxEntries` 的条目仍存入文档数据，但不渲染/不导出。
- 当前 `Entry` 无 visible 字段，且规格以「与照片槽换模板同语义」描述——采用**顺序语义**：
  - 用户在确认界面勾选「优先显示」的条目；**勾选条目排在分区前部，未勾选条目追加在后**；
  - 模板按 `maxEntries` 渲染前 N 条，未渲染条目仍在 `doc.sections[].entries` 中，换模板/提高上限后自然出现。
- UI 必须写明「超出上限的条目会保存在数据里，当前模板不显示、不进入导出」，避免误以为被删除。

### 2.5 落库与失败语义

- 解析阶段**不建记录**；仅在完成步一次性创建（复用 library 的写入串行链与 `WriteOutcome`）。
- 创建成功 → 打开新简历进入编辑器；刷新失败 → 提示「已创建但列表未刷新」（记录已存在，不重复创建）。
- 解析失败/无文本：留在向导并显示可操作错误（换文件/改粘贴），不产生半成品记录。
- 关闭窗口时向导进行中 = **未完成状态**（§5.7）：走 `CloseGuard` 的「丢弃并关闭 / 继续编辑」；离开向导需确认丢弃草稿。

### 2.6 入口

- 库页导入区替换为真入口：**拖入区 + 浏览 + 粘贴文本**；空态恢复「投放区放大居中 + 三模板快捷」。
- m1.4 大段粘贴气泡的「去导入」按钮接向导，并**预填该次粘贴文本**；导入完成打开新简历，原文档不受影响。

## 3. 否决方案

| 方案 | 否决理由 |
|---|---|
| m1.7 接 LLM 结构化 | 需提前做模型连接/Key 管理（m3.5），范围失控；离线/无 Key 时导入不可用 |
| 零依赖自研 DOCX/PDF 解析 | 编号、表格、分栏、编码边界多，维护成本高；规格已指名 mammoth/pdf.js |
| 真 Tauri 第二窗口 | 需提前 m2.3 的窗口基建（capabilities/跨窗状态/关闭保护），且导入完成后库页刷新需跨窗事件 |
| 只解析成文本块、用户手工分区 | 用户已拍板启发式结构化；手工分区作为「未归类池」的兜底保留 |
