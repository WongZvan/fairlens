# 第四轮用户级文档挖掘（2026-10-25）

> 方法：换三个前几轮未用的维度——规则间冲突、时间与规模维度、角色与权限假设——对照三份用户级文件全文压力测试。发现 7 缺口（1 中 + 6 低，无高级别）+ 1 项 FairLens 侧偏离。重点结论：**启动协议是强建议而非强制**——真实场景（FairLens 五轮中多次直接说"开工"）已证明用户会跳过核对，AI 需要的是"跳过时主动声明"而非拦截。

## 🟡 中（4 条）

1. **启动协议缺豁免出口**：用户跳过核对直接说"开工"时三文件沉默——协议无强制力定义。→ SOP §4/START-COMMANDS 命令 1 补：启动协议为强建议；用户跳过时 AI 须主动声明"已跳过核对，悬挂事项共 N 条"——提示不拦截。
2. **AGENTS.md 副本回灌时机未闭环**（G-D 只写"扫描"没写触发与判定）：→ SOP §11 补：回灌触发=用户级 Changelog 日期晚于项目副本复制日期；判定=逐节 diff。
3. **decisions/ 升级动作无仪式**：偏离节→总账升级=复制内容还是移走？双向断链风险。→ DOC-SPEC §B-7 补：升级=decisions 建正式条目+偏离节原条目改一行指针（防双源）。
4. **三文件无适用前提声明**：假设 AI 具备文件读写与命令执行能力；纯对话型 AI 加载后整套状态层例程失效。→ SOP/DOC-SPEC 头部加"适用前提"一行。

## 🟢 低（3 条）

5. **触发短语误识别**：用户日常对话自然说出"继续"会被语义捕获为命令。→ START-COMMANDS 补判别规则：命令仅在会话开始/模块收口后/明确语境触发；对话中段按自然语言理解。
6. **G-G Changelog 自举缺口**：初版前修订无记录。→ 三文件 Changelog 首行补"初版前修订未记录"。
7. **总账无状态标记语法**：活跃/已被修订/已移除三态未成文。→ 总账格式约定补三态标记。
