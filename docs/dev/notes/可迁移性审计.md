# 可迁移性审计（内部工作底稿，2026-10-25）

> 场景：三份用户级文档（SOP/DOC-SPEC/START-COMMANDS）若迁移给其他模型（GPT/Gemini/开源模型）或其他 agent 框架（Claude Code/Cursor/通用 AGENTS.md），哪里会断？

## 依赖盘点（迁移断点）

| # | 依赖点 | 出处 | 其他框架是否有等价物 | 断裂程度 |
|---|---|---|---|---|
| 1 | **AI 持久记忆**（"已登记持久记忆，任何新会话均识别"——START-COMMANDS×2/SOP×2） | ZCode 项目级记忆目录 | Claude Code=memory 工具/CLAUDE.md；Cursor=无原生等价；开源 agent=无 | 🔴 命令识别依赖此——换框架即失效 |
| 2 | **`.agents/skills/` 目录**（skill 自由使用条款引用的技能库） | ZCode 技能格式（SKILL.md） | Claude Code=skills 兼容格式相近；Cursor=rules 机制不同 | 🟡 部分可迁移（不在迁移范围，按需重建） |
| 3 | **触发短语**（"核对状态层"等六条） | START-COMMANDS | 短语本身框架无关——但**识别**依赖 #1 持久记忆 | 🔴 与 #1 同源 |
| 4 | **路径假设** `~/.agents/` | 三文件互引 | 通用 POSIX 路径，框架无关 | 🟢 无断裂 |
| 5 | **AGENTS.md 复制机制** | SOP | AGENTS.md 已是跨框架事实标准（Claude Code/Cursor/开源均读） | 🟢 无断裂 |
| 6 | **docs/dev 状态层** | DOC-SPEC | 纯 Markdown 文件读写，任何能读文件的 agent 均可 | 🟢 无断裂 |

## 结论

**文档内容 95% 可迁移**（AGENTS.md 机制+状态层 Markdown 是框架无关的），**断裂点集中在"跨会话识别"**——即"已登记持久记忆"这个假设。三文件已加「跨框架迁移」节（自包含化方案）：迁移三步 + 等价机制对照表直接写在文档头部，换框架时照节执行即可。

## 迁移步骤（已写入三文件）

1. 复制三文件到新框架的等价位置（SOP→AGENTS.md/CLAUDE.md/规则文件；START-COMMANDS→其记忆或系统提示）；
2. 把「持久记忆依赖」条目替换为新框架的等价机制说明；
3. 触发短语本身不变——新框架的规则文件里写明"用户以下列短语发起工作时按对应例程响应"。
