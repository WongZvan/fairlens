## 1. 产品定义（PRD）

### 1.1 定位

FairLens 是**画布式（WYSIWYG）简历工作台**：中间工作区就是简历成品（真 A4 画布，编辑即所见=导出）；AI 以块级内联 diff 修订与红笔批注两种形态深度嵌入；评估结论行内直达；面向按批次组织的面试候选人，授权使用。

### 1.2 用户画像与角色

| 角色 | 描述 | 进入方式 |
|---|---|---|
| 候选人（普通授权用户） | 多批次面试候选人，多为非技术背景 | 激活码（一码一机，无需注册；**激活码即邀请码，无独立注册流**） |
| 内部开发者 | 你/团队，提示词调优与调试 | dev key（**有效期无限制**，泄露靠吊销兜底） |
| 客户方组织者 | 批次管理、激活码分发 | 无软件角色；CSV 分发 + 人工反馈 |

### 1.3 用户故事（15 条，含验收标准）

**候选人（8）**
1. 装机激活：我能 10 分钟内完成安装并激活 → 验收：全新 Win10/11 机器安装→激活→进入首页 ≤10 分钟，无手册依赖。
2. 配置 AI：我能按预设填 Key 并确认可用 → 验收：选预设→贴 Key→拉模型列表→测试连通绿色徽章，全程无报错求助。
3. 导入旧简历：我能拖入 DOCX/PDF 得到结构化简历 → 验收：导入→LLM 结构化→逐区确认后结构树完整、内容无丢失。
4. 块级修订：我能对一句话要 AI 改写并采纳 → 验收：Ctrl+Enter→流式建议→内联 diff→采纳自动快照、Ctrl+Z 一次撤销整条。
5. 全篇评估：我能得到可读的评估报告与批注 → 验收：雷达图+总分+批注可点击跳转对应块。
6. 批注走查：我能像导师批改一样逐条过问题 → 验收：走查按条目逐条浮现批注，启动前显示 Token 估算。
7. 导出交付：我能导出可投递的 PDF/Word 与求助用的批注长图 → 验收：PDF 链接可点、Word 可编辑、长图 2x 清晰。
8. 换机迁移：我能把简历连同历史迁到新电脑 → 验收：解绑→新机同码激活→导入 .fairlens 档案，简历/快照/评估全恢复。

**内部开发者（4）**
9. 提示词调优：我能在应用内改提示词并真实调试 → 验收：Prompt Studio 改模板→调试台见完整合成提示词与原始响应。
10. 热更新发布：我发布新提示词不需要发版 → 验收：签名包 push 后候选端 ≤4h（或手动刷新/评估前）生效。
11. 批次签码：我能 10 分钟为一批次签 200 个码 → 验收：keygen issue 产出 CSV 且 KV provision 完成。
12. 吊销管控：我能即时停掉泄露的码 → 验收：revoke 后最迟 7 天（renew 时）该码全部设备冻结。

**客户方组织者（3）**
13. 批次分发：CSV 拿到即发（含说明） → 验收：候选人凭链接+码自助完成故事 1。
14. 效果留档：能收到候选人的批注版文件作为批次证据 → 验收：批注版 HTML/PNG 无需安装即可打开。
15. 反馈通道：无遥测依赖，靠群内诊断码人工反馈 → 验收：配置失败时一键复制诊断（错误码+厂商，不含 Key）。

### 1.4 端到端用户旅程（候选人八步）

```
①装机   下载 setup.exe(~10MB)→协议页勾选→选路径→安装(WebView2缺失自动引导)
②激活   输激活码→本地验签+在线占席(一码一机)→进入简历库首页
③配AI   设置→模型连接→预设→Key→拉模型列表→测试连通→场景分配
④建简历 选模板新建 / 拖入DOCX·PDF / 粘贴 → LLM结构化 → 逐区确认
⑤打磨   Ctrl+Enter块级修订(diff采纳/拒绝)→Ctrl+Shift+E评估(红笔+雷达)
        →点批注跳回对应块→可选AI走查→快照对比/回滚
⑥导出   导出下拉:PDF/Word定稿;批注长图发群;节点归档备份(.fairlens)
⑦换机   旧机解绑退出→新机同码激活→导入.fairlens全恢复
⑧无感   72h自动续租/4h提示词更新/自动升级/断网7天宽限
```

### 1.5 差异化定位（第二轮审计增）

**vs 花模板简历工具**（超级简历/五百丁类）：我们卖的不是模板量（3 套克制版式），是 **AI 打磨闭环**（块级修订+红笔批注+评估回环）与 **HR 友好的专业观感**；版式锁定保证导出永不损坏。**vs 直接用通用 AI**（ChatGPT 贴文本）：结构化文档模型（块锚点/diff/快照可回滚）、本地隐私（简历不出本机）、垂类提示词热更、批次授权管控。目标市场=客户方组织的面试辅导批次，非自由 C 端——克制策略与该场景价值观吻合（风险记录见 §16）。

### 1.6 客户方成功指标与证明方式（零遥测原则下的价值证明链）

| 指标 | 证明方式 |
|---|---|
| 激活完成率 | keygen 台账（provision 数）vs KV activate 记录对账 |
| AI 配置率 | 续租一比特（aiOn/aiOff 计数） |
| 批次效果留档 | 候选人批注版文件回收（HTML/PNG 免安装可开） |
| 修订效果 | 快照前后对比抽样 + 客户方人工反馈汇总 |

### 1.7 范围铁律（v1 明确不做）计算机垂类工作台（**1.0 预留** VerticalCapability）；机构 Key 网关（**0.2 候选**，触发条件：首批次 Key 配置失败率 >20%——经续租一比特统计——或客户方明确要求零配置）；.dotx 模板导入；多人协作/云同步/Web 版（**1.0 路线图**）；常驻自维护服务器（唯一服务端为 ~100 行租赁函数）；商务定价（客户方批次付费模式）属商务文档，不在本文档范围。

### 1.6 非功能需求

| 项 | 指标 |
|---|---|
| 性能 | 打字零可感知延迟；3 页简历滚动 60fps；冷启动 <2s；SSE 按 rAF 批量上屏 |
| 隐私 | 简历/评估/Key 不出本机；出网仅四类流量（见 §2）；AI 首用 consent |
| 可用性 | 断网宽限 7 天（冻结至仅查看/导出）；中文 IME 无异常；键盘全操作 |
| 品质 | 每里程碑 DoD 首条=测试全绿；纯逻辑包覆盖率 ≥80%；UI 反通用审美（§12） |

**数据边界铁律**：出网流量仅四类——① Releases 更新 ② 租赁端点（仅 code+设备哈希+一比特） ③ dist/ 只读拉取 ④ 用户自有 Key 的 LLM 直连。

### 2.2 三投影模型

```
ResumeDoc + TemplateManifest（语义模型=唯一数据源）
 ├─ 画布: 模板导出 CSS 在 WebView 直接渲染（编辑样式=导出样式）
 ├─ PDF : 同一 CSS 经 WebView2 CDP printToPDF（矢量/链接注记/精确分页）
 └─ Word: docx 库按模板令牌构建原生 .docx（真段落/标记/链接，可编辑）
```

用户只编辑语义模型；版式不可损坏是结构保证。画布内分页线为 CSS 近似，精确以导出为准（同引擎，M5 验收）。

### 2.3 分层职责与禁止事项

| 层 | 职责 | 禁止 |
|---|---|---|
| WebView UI | 全部交互/画布/AI 编排/导出编排 | 系统 I/O（AI 出口除外） |
| packages/core | 纯 TS：diff-apply/评估管道/双证状态机/LLM 客户端/SSE 解析/提示词渲染 | 依赖 DOM/Tauri API |
| packages/shared | 全部 zod 契约（§4） | 含逻辑 |
| packages/prompts | 内置兜底提示词包+校验 | 业务逻辑 |
| functions/lease | 席位租约 KV 读写（~100 行，契约见 §10.3） | 接触简历数据/内嵌公钥 |
| tools/keygen | 签发/吊销/签名/归档工具 | 私钥入仓 |
| Rust 层 | 系统能力宿主 | 业务逻辑（红线 <300 行） |

### 2.4 扩展性架构：注册表与预留接口（v1.7，防补丁式腐化）

**五大注册表/抽象——类型先行进 shared（即使 v1 只有一个实现；预留的是类型与插槽，不是猜测的代码）**：

```ts
CapabilityRegistry   // 垂类能力：1.0 的 code-editor/question-bank 插入点（id+工作台组件+命令+设置节）
LlmGateway           // 更名 **AiGateway**（v1.9 多模态命名预留）：'direct'（自有Key，v1）| 'institutional'（机构网关，v1.1）—— ScenarioRouter 解析；generateImage/transcribe 等多模态方法按需扩展
ExporterRegistry     // pdf/docx/png/html/fairlens 各实现 Exporter 接口，新导出=加条目
ImporterRegistry     // paste/docx/pdf/archive（未来：LinkedIn/招聘站导出文件）
PackSource           // builtin | github-dist（v1）| server-market（未来资源市场）
```

**防腐四规则**：① 依赖方向单向 `shared←core←features`，跨 feature 禁 import（eslint boundaries 进 CI 门禁）；② **注册表优先检查单**——新功能先找已有插槽，无位则先扩注册表再插入，核心布线零改动；③ SQLite 迁移策略：`user_version` + 顺序迁移脚本，杜绝 schema 债；④ 文件规模预算（core 模块 ≤400 行/feature ≤15 文件，超限拆分）。

## 3. 工程结构与开发流程

### 3.1 Monorepo（开源主仓 public——jsDelivr 镜像前提）

```
fairlens/
├─ pnpm-workspace.yaml            # apps/* packages/* functions/* tools/*
├─ .github/workflows/             # ci.yml(三门禁) release.yml(tauri-action，含 macOS 矩阵占位 disabled) lease.yml(部署)
├─ dist/                          # prompts/<verticalId>/ templates/<id>/ guides/*.md
├─ functions/lease/               # CF Worker(fetch handler 可平移腾讯云)
├─ tools/keygen/                  # init/issue/pack/revoke/unbind/archive
├─ apps/desktop/                  # src/(app,design-system,features/*,stores,lib) + src-tauri/
└─ packages/{shared,core,prompts}/
```

**工程注记（第四轮）**：CI 第三方 actions 一律版本 pin；pnpm lockfile 入仓（可复现构建）。

**命名约定**：TS 字段 camelCase；SQL 列 snake_case；Tauri command snake_case；CSS 变量 `--ade-*`；zod schema PascalCase；文件 kebab-case。

### 3.2 Git 三层分支隔离

- **main**：稳定基线；仅接受合并；**禁止 force push**；里程碑收口（M1–M5 各一次 dev→main 合并）与发布打 tag `v*`（触发 release 流水线）。
- **dev**：日常集成分支；CI 三门禁常跑；与 main 差距 ≤ 一个里程碑；**禁止 force push**。
- **feat/&lt;模块&gt;-&lt;主题&gt; / fix/* / docs/***：短生命周期（≤3 天），自 dev 切出，**squash 合回 dev**。
- **提交规范**：Conventional Commits（feat/fix/docs/chore），描述关联里程碑。
- **三层回滚**：代码=git revert（main 历史永不重写）；发布=更高版本修复或 latest.json 指回旧版；提示词包=git revert dist/ 提交。恢复点=每里程碑 main tag。
- **首推远端保护清单**：main/dev 禁 force push；main 需 CI 绿灯；tag 受保护。
- **状态层轻量通道（#97 定案）**：`docs/dev/**` 与 docs 类单文件更新豁免 feat 分支——直接提交 dev 并推送（仍禁 main 直推/禁 force push）；**代码一律走 feat**（悬挂事项/索引同步是会话级高频小更新，squash 是流程税）。

### 3.3 环境分离（严格 dev/prod，六维矩阵+密码学互斥）

| 维度 | 开发环境 | 生产环境 |
|---|---|---|
| Ed25519 密钥对 | dev 密钥对 | prod 密钥对（**跨环境激活码验签必然失败**） |
| 应用标识 | `com.fairlens.desktop.dev`（独立数据目录，可与正式版共存） | `com.fairlens.desktop` |

### 3.4 AI 辅助开发约定（v1.7）

开发过程中**可自由使用可用技能（skill）与工具**——UI 预览渲染、测试驱动开发（TDD）、浏览器/前端验证、设计审查、文档处理、代码检索等——前提：这些动作服务于本项目功能开发与设计质量的提升。本约定不豁免既有纪律：文档先行（先改 §总账与正文再写码）、每阶段测试门禁、三层分支隔离、环境分离。

### 3.5 分模块开发顺序与单产品·角色驱动功能面（v1.11）

**单产品原则**：一个代码库、一个安装包、一次发布。功能面由**激活码内嵌 role**（License 验签）驱动——`user`→基础功能面；`dev`→基础面+开发者六件套（§6.5）；`expert`（1.0 预留）→基础面+专家简化界面。**不存在两个产品、两个安装包**。

**工程四规则**：① dev 专属模块独立路由前缀+**懒加载分包**（role≠dev 不加载 chunk，普通用户不可见不可达且减首屏）；② **门控单点**：角色判定唯一来源=LicenseClaims.role 验签结果，路由守卫与 UI 显隐同源；③ **测试三套**：基础面 E2E（user 码全绿且断言 dev 入口不可见不可达）/dev 面独立测试（dev 码）/越权测试（user 码直访 dev 路由被拒）；④ 同包异面，维护成本不变。

**分模块顺序（29 单元=feat 分支粒度；三原则：契约先行/风险前置/依赖驱动+垂直可用——每阶段收尾产品可运行可演示）**：

### 3.6 目录层级开发状态与模块导航（v0.1 增补，2026-10-24）

**目的**：跨会话/上下文交接时进度与细节可对齐，杜绝凭记忆编造字段名。**结构**：`docs/dev/` = STATE.md（进度快照：里程碑/分支/tag/环境实录）+ `modules/`（**29 模块各持一个开发细节 MD**：状态/规格锚点/任务清单/实现要点（回填）/验收/偏离；`modules/README.md`=导航总表）+ `decisions/`（**需用户裁决的范围转向/架构权衡**，ADR-lite；模块 MD 偏离节=默认记录点承担过程小教训，两者互链——#97 定案）+ `notes/`（环境坑实录）。**规则**：①模块收口=回填实现要点+同步 STATE 与导航表（并入 DoD），**同步后执行勾选一致性核对**——STATE 各行与导航表状态/commit/分支逐项互检，漂移当场修复（2026-10-24 核对实证价值，commit 363efb7 修复三处）；①′**决策传播**：总账新增/修改决策时，必须同步更新**所有受影响模块 MD** 的任务清单/规格锚点（不止 docs/01 与单一模块——含实现方与预留方两侧）；②**字段名唯一事实源=本文档与 packages/shared/src，禁止凭记忆引用**——状态层只存指针不复制契约；③**新会话启动协议**：**第 0 步读 STATE「悬挂事项」节**（待决策/待人工验收/占位账）→ STATE → 当前模块 MD → 本文档对应章节 → `git log --oneline -20` → 开工。**交接前对齐**（会话结束前）：更新 STATE 悬挂事项节——把仅存在于对话中的待决策/待人工验收/占位账写下来，防上下文切换丢失。

### 3.7 缺陷直报与即修协议（v0.1 增补）

开发中发现逻辑错误或设计缺陷时：**必须向用户直报**（附证据：文件/行/复现路径）；在既定决策范围内**直接修复**并配回归测试（先红后绿），超出范围则给出方案待裁决；每次处置记入 `docs/dev/decisions/`；已发布版本的缺陷走 `fix/*` 分支 + 0.1.x 补丁。审计关闭（§16）不豁免开发期的即时纠错义务。

**跨模块历史缺陷（旧坑）细则（v0.1 增补）**：在当前模块开发中发现的缺陷**不分新旧**（可能来自任意已收口模块），一律走本协议。补充四条：

1. **状态规则**：已收口模块发现 bug 不降级状态，该模块 MD 偏离节追加"回归修复（由 mX.Y 开发期间发现）"；若缺陷暴露 DoD 本身漏项→同步修订该模块 MD 验收节。
2. **分支策略**：小修（单点/不改契约）→ 当前 feat 分支顺带修，commit 标注 `fix(mX.Y 回归):`；大修（跨模块/改契约/影响当前模块交付）→ 先收束当前工作（squash 回 dev 或 stash），切独立 `fix/mX.Y-*` 分支。
3. **测试回补落点**：回归测试补到**缺陷所属模块**的测试集（非当前模块）；若是测试门禁漏网→同步补 §14 对应条目。
4. **定性分流**：纯 bug 走本协议；"没完全实现"（DoD 缺口）按 §3.8 T2 范围变更走（补实现+补测试）。

### 3.8 范围变更三级程序（v0.1 增补，2026-10-24）

**触发**：任一模块开发中/收口后，突发需要临时**增加/删除/修正功能**。防"目标文档与落地交付漂移"：**T2/T3 传播链未走完前，不开工该变更的代码**（文档先行铁律特化）。

| 级别 | 定义 | 程序 |
|---|---|---|
| **T1 实现级** | 不改用户可见行为/契约（bug 修正/实现细节调整） | §3.7 缺陷直报即修：直报→修→回归（先红后绿）→模块 MD 偏离节。无需总账 |
| **T2 功能增删改**（模块内） | 用户可感知，不动范围铁律/不增删整个模块 | ① 向用户直报方案（证据+影响面）→ 拍板；② **传播九处清单**（见下）；③ 回归测试 |
| **T3 结构级** | 新增/删除整个模块 / 里程碑 DAG 变化 / 触碰范围铁律 | T2 全部 + §3.5 顺序表与导航表增删行 + **砍掉项移入附录 F 路线图（永不直接消失）** + §11.2 工期成本表更新 |

**T2/T3 传播九处清单**（逐处勾选，缺一即漂移）：
1. 附录 E 决策总账（新增/修订条目+理由）
2. 01 正文受影响章节（范围铁律/契约/模块表行/机制描述）
3. 该模块 MD（任务清单/规格锚点/偏离节）
4. **受影响相邻模块 MD**（实现方+预留方两侧——传播 ①′）
5. 导航表（modules/README.md 状态与分支列）
6. STATE.md（悬挂事项若在途/已落地行）
7. §14 测试策略对应条目（新增测试/修改验收）
8. §15 里程碑 DoD（若影响交付叙事）
9. §11.2 工期成本表（若影响估算）

### 5.3 节点 ↔ ResumeDoc 映射

### 5.6 快照/导入/快捷键/命令面板

### 5.7 关闭保护与文件打开（v1.4）

**关闭保护双模式**（设置→通用→「自动保存」开关，默认开）：

| | 默认模式（自动保存 ON） | 手动模式（OFF，Word 式） |
|---|---|---|
| 保存 | 防抖自动落盘；**关闭时同步 flush**（本地 SQLite <50ms，内容永不丢） | 手动 Ctrl+S；标题栏 ●未保存 dirty 标记 |

| 维度 | 选项 | 效果 |

| 字体主题 | 模板 2–4 套调校搭配（宋体系/黑体系等） | 标题+正文字体整体切换；字体随应用打包（HTML/PDF 子集内嵌），docx 映射 Windows 安全字体链 |

## 10. 授权与后端解耦

### 10.1 双证时序（含幂等恢复边——v1.2 审查修复）

```
激活: 验签(公钥内置)+exp → POST /lease acquire → 席位空闲→双证缓存→进入
      失败→bad-signature/expired/revoked/unknown-code(未provision)/slots-full(附解绑指引)
续租: 每72h renew → 在册未吊销→延7d（顺带 aiConfigured 一比特累计）
断网: 沿用租约至 TTL(7天) → 冻结(仅查看/导出)
恢复: lease 过期后联网 → 自动同 code+deviceIdHash 重新 acquire（幂等占席，用户无感）
      → slots-full 则提示解绑指引                        ← 审查修复新增迁移边
换机: 旧机 release(或设置「解绑本机并退出」——**解绑归档保护**：若本机存在简历数据，先弹「导出档案(.fairlens)再解绑」引导，可勾选"我已导出/不需要"跳过) → 新机 acquire → 导入 .fairlens
吊销: KV 标记 → 最迟 7 天(renew 时)全部设备冻结
```

### 10.2 KV 记录（设备数唯一执行源）

```
code → { devices: [{ id: deviceIdHash, exp }], revoked: bool,
         maxN: number, batchId: string, aiOn: number, aiOff: number,
         plan?: PlanQuota }   // v1.10 类型位（v1 不写入）：{ name; monthlyTokenCap?; rpm?; priority? }——机构套餐/限流配额
```
`keygen issue` 签发时即调 `/admin/provision` 预建（未预建码 acquire=unknown-code）；KV 丢失由 keygen 台账 CSV 重放全量重建。

### 10.3 lease API（契约先行：CI 从 shared zod 导出冻结 `lease-api.v1.json`，桌面端与 Worker 双侧校验零漂移，漂移即红灯）

```
POST /v1/lease   { action:'acquire'|'renew'|'release', code, deviceIdHash, aiConfigured? }
  → { ok:true, lease } | { ok:false, code: ErrorCode }
POST /v1/admin/provision { code, maxN, batchId }   Bearer ADMIN_KEY（keygen 专用）
POST /v1/admin/revoke    { code } / unbind { code, all? }
```
部署：CF Worker+KV 双环境+自定义域名（workers.dev 国内直连差；腾讯云搬迁路径需域名备案——部署期验证）；~100 行无状态；IP 限流+密钥格式本地预检；KV 同秒抢席可能瞬时超额一席（7 天收敛，接受残余）。

### 10.4 后端解耦策略（可拆仓单独开发）

**单一接触点**：桌面端对后端全部感知收敛为 `LicenseProvider` 接口+core/license-lease HTTP client。契约版本化（/v1，不兼容变更升 v2 并行）；CI path filter（仅 functions/** 与契约变更触发部署 job，桌面改动永不部署后端反之亦然）；**拆仓预案**：搬 functions/+契约 json，桌面端改一行依赖指向；触发条件=后端多人开发或引入第二个服务端模块。

### 10.5 keygen CLI

| 命令 | 作用 |
|---|---|
| `keygen init` | 生成 dev/prod 双 Ed25519 密钥对（prod 公钥编译进正式构建；私钥加密离线**双备份**绝不入仓） |
| `keygen issue --env dev\|prod --batch --role --days --max-devices --count --out` | 签发+provision → CSV 台账（列：code,key,batch,role,exp,max_devices,issued_at）＝灾备重放源 |
| `keygen pack --dir` | 校验+签名提示词包/模板包 → dist/ |
| `keygen revoke --code` / `unbind --code [--all]` | 吊销/清席（--env 必填，缺省拒绝） |

### 11.1 分发

### 12.3 动效与丝滑

克制精准：微交互 120–160ms/面板 240ms/spring(≈400/40)；批注一次入场不循环；打字零动画；prefers-reduced-motion 全降级。插件 motion+dnd-kit（不用 GSAP/Lottie）。工程规格：模板 CSS containment 隔离画布子树；SQLite 异步落盘；transform/opacity only；冷启动<2s。**离线指示（状态栏左端）**：在线=绿点；离线=灰点+「离线：AI 与更新不可用」tooltip；AI 请求断网失败错误文案统一"当前离线"。**小屏适配（第三轮审计）**：最小窗口 1152×720；左树/右评估面板可折叠（折叠钮+快捷键），1366px 下画布优先保宽。**工具栏增撤销/重做按钮**（Word 肌肉记忆，Ctrl+Z/Y 保留）。**错误文案表**：ErrorCode/HTTP 错误→一句用户语言+下一步动作（如 401→"Key 无效，请重新粘贴或换厂商"），实现在 design-system 文案层。

### 12.4 禁用清单（反 AI 通用审美）

米色+衬线+陶土橙 / 近黑+酸性绿 / 报纸细线框三套路；紫蓝渐变、玻璃拟态、Lottie、大圆角糊膏、界面 emoji、逐 token 淡入。签名元素唯一：红笔批注系统（仅红绿两笔色+下划线/波浪线两笔触）。**无障碍注记**：批注采用颜色+笔触形状（下划线/波浪）+位置（页边卡）三重冗余编码，色弱用户可辨。**图标规格（第四轮）**：lucide、16px 默认线宽、仅 UI 域——**纸面永无图标（纸是印刷品）**。**字体许可合规（第四轮）**：IBM Plex/Noto Serif SC 均 OFL 开源可随包分发；楷体=系统字体引用不打包（规避版权）。

  template_id TEXT NOT NULL, doc_json TEXT NOT NULL, status TEXT NOT NULL DEFAULT 'active',
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL);

  doc_json TEXT NOT NULL, template_id TEXT NOT NULL, label TEXT,
  trigger TEXT NOT NULL CHECK(trigger IN('ai-accept','manual','pre-eval')), created_at TEXT NOT NULL);

CREATE TABLE review_sessions(id TEXT PRIMARY KEY, resume_id TEXT NOT NULL REFERENCES resumes(id) ON DELETE CASCADE,
  source TEXT NOT NULL CHECK(source IN('evaluation','walkthrough')), report_json TEXT NOT NULL, created_at TEXT NOT NULL);
CREATE INDEX idx_reviews_resume ON review_sessions(resume_id, created_at DESC);
CREATE TABLE ai_patch_log(id TEXT PRIMARY KEY, resume_id TEXT NOT NULL, block_id TEXT NOT NULL, action TEXT NOT NULL,
  prompt_version INTEGER NOT NULL, model TEXT NOT NULL, original_text TEXT NOT NULL, suggested_text TEXT NOT NULL,
  accepted INTEGER NOT NULL, created_at TEXT NOT NULL);
CREATE INDEX idx_patch_resume ON ai_patch_log(resume_id, created_at DESC);
CREATE TABLE settings(key TEXT PRIMARY KEY, value_json TEXT NOT NULL);
